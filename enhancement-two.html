Narrative

Artifact Description

The artifact is TreasureHuntGame, a Python/Jupyter notebook created for CS 370: Current and Emerging Trends in Computer Science. It uses deep Q-learning to train a pirate agent to navigate a maze and find treasure. A Keras neural network predicts the value of each possible move, while the qtrain() function trains the agent through thousands of simulated games. The system uses experience replay and a target network to make training more stable. The maze and replay memory are handled through separate support modules, TreasureMaze.py and GameExperience.py.

Justification for Inclusion

I selected this artifact for the Algorithms and Data Structures category because it involves a clear algorithmic decision about how training experiences are stored and sampled. It also connects to my goal of becoming a game developer because reinforcement learning and game AI both depend on efficient decision-making and data structures.

My enhancement focused on the replay memory in GameExperience.py. My original Module One plan included four possible enhancements, but two were already present in the actual course code. The main problem I found was that the replay memory used a basic Python list. Removing the oldest entry required an O(n) shift, and experiences were sampled uniformly at random without considering which ones were most useful.

I replaced the list with Prioritized Experience Replay (PER) using a SumTree. The SumTree stores priorities in a binary tree, allowing new experiences to be inserted in O(1) time and sampled in O(log n) time. Experiences with larger TD-errors are given higher priority because they represent situations the model is still having difficulty learning. I kept the original remember(), predict(), and get_data() interfaces, so qtrain() did not need to be changed. I also created 12 automated tests to verify the SumTree and replay memory without requiring TensorFlow.

Course Outcomes: Met and Updated

My Module One plan targeted Outcomes 3 and 4 with four enhancements: bounded replay memory, prioritized sampling, a hash set for visited cells, and a decaying exploration rate.

After examining the code of the files I had not planned to change, I found that the maze already used a Python set() to track visited cells, and the training loop already decreased epsilon toward a minimum value. Because those features were already implemented, they did not need to be enhanced. The other two parts of my plan were still relevant, so I combined them into the full SumTree-based prioritized replay system.

  • Outcome 3: The SumTree improves the algorithm's time complexity by making insertion O(1) and sampling O(log n), while prioritizing experiences that provide more useful training information. Keeping the original interfaces was a deliberate trade-off that limited the change to one module.
  • Outcome 4: I implemented Prioritized Experience Replay based on the approach described by Schaul et al. (2015) and verified the implementation with automated tests.

Outcome 5 was not targeted by this enhancement because the artifact does not handle user input or sensitive data; security is addressed in Enhancement Three.

Reflection

The biggest lesson from this enhancement was the same one I learned during my first enhancement: verify the actual code before building a plan around assumptions. My Module One plan was partly based on features I expected to find, but two of them were already implemented. A plan is useful, but it cannot replace examining the code.

Another challenge was that TreasureMaze.py and GameExperience.py were imported modules and were not included in the notebook's HTML export. I had to rebuild them using the public version of the assignment files, the course specifications, and the instructor's starter notebook. This helped me confirm how the original system was designed instead of relying on assumptions.

The most technical challenge was getting the SumTree indexing correct. Parent nodes must always contain the sum of their children, and even a small indexing error can cause incorrect sampling. My unit tests using manually calculated priority ranges caught an off-by-one error in my first version before it affected the training system. This reinforced how important automated testing is when working with data structures.
